## Статус реализации

- Реализованы Auth, отдельные локальные базы аккаунтов, транзакционная очередь, курсоры, повторы, конфликты, события обучения, приватные изображения, перенос гостевой библиотеки, локальный сброс кэша и серверное удаление аккаунта.
- Содержимое карточек и личный начальный прогресс физически разделены: `sync_record_data` и `card_progress`. `sync_records` — совместимое представление для синхронизации; события обучения хранятся отдельно от содержимого. Остальные сущности передаются типизированными JSONB-документами.
- Крупные операции загружаются возобновляемыми частями, затем применяются атомарно. Локальная очередь имеет отдельный монотонный порядок, который не зависит от часов устройства.
- Очистка старых осиротевших файлов и удаление всех файлов аккаунта реализованы серверными функциями. Очистка защищена блокировкой, учитывает живые ссылки, черновики и незавершённые импорты.
- Перед запуском облачной версии остаются SMTP, настройки Auth на домен easy-learn.pages.dev, настройка публичных переменных Cloudflare и пересборка, production-проверки и уведомления о квотах. Подробности и команды: [CLOUD_SETUP.md](CLOUD_SETUP.md). Правила данных и карта записей: [CLOUD_DATA_RULES.md](CLOUD_DATA_RULES.md).

## Принятое направление

Cloudflare Pages раздаёт собранный сайт. Supabase предоставляет Auth, PostgreSQL, API и Storage. Dexie остаётся локальной базой, из которой работает интерфейс. Отдельный постоянный Node-сервер для первого выпуска не нужен; привилегированные операции выполняются серверными функциями.

Изменение пользователя → локальная транзакция с очередью операций → отправка в Supabase → подтверждение и получение изменений → обновление Dexie.

Сохранить гостевой локальный режим. Облачные данные первой версии приватные. Публичные библиотеки и совместное редактирование отложить. Подготовленный каталог оставить в статических файлах, а персональные изменения и прогресс синхронизировать отдельно.

## Порядок реализации

1. Правила данных и исходные проверки.
2. Миграции PostgreSQL, RLS и изоляция локальных пространств.
3. Auth и безопасный перенос гостевых данных.
4. Синхронизация одной колоды на двух устройствах.
5. Прогресс, тесты, остальные материалы и изображения.
6. Копии, удаления, PWA, preview и полный набор проверок.
7. Production-выпуск.

Не считать регистрацию законченной облачной интеграцией: до публичного запуска обязательны изоляция аккаунтов, сохранность локальных данных, повторяемая синхронизация и проверка доступа.
