# Индексы, пакетные операции и надёжность данных

## Локальная база

IndexedDB обновляется автоматически: гостевая схема 2 → 3, схема аккаунта 4 → 5. Миграция сохраняет карточки, историю, черновики и порядок очереди. Старые соединения закрываются при обновлении схемы; старые вкладки следует перезагрузить.

Добавлены индексы `[language+nativeLanguage]`, `decks.*wordIds`, `collections.*deckIds`, `collections.folderId`, `[wordId+timestamp]`, `outbox.*recordKeys`. Для ранее накопленной очереди `recordKeys` заполняется в миграции.

- CSV: одна выборка карточек нужной языковой пары, поиск дублей через Map, один bulkAdd и одно обновление членства колоды. Статистика добавляется одной операцией. Ошибка строки откатывает импорт целиком.
- Публикация колоды: пакетное чтение оригиналов и один bulkPut изменённых карточек. Сохраняются идентификаторы общих карточек и история обучения.
- Удаление карточек/колод: индекс находит только затронутые колоды/модули; несвязанные записи не переписываются.
- Захват массовой записи для облака: Map вместо повторного поиска по массиву; 1 000 карточек требуют две пакетные записи служебных данных, а не отдельную запись для каждой карточки.
- Оценка ответа: индексная выборка первого подходящего события вместо загрузки всей истории карточки.
- Очередь: снимок верхней границы порядка, чтение порциями по 50, проверка ожидающих записей по индексу без загрузки всех before/value. Изменения, возникшие во время загрузки, остаются видимыми и отправляются следующей попыткой.
- Производные данные: пересчитываются затронутые карточки и дни. Записи одинаковых результатов пропускаются; lastStudiedAt обновляется один раз на колоду, а не для каждого события.
- Черновики: синхронный журнал текста, объединение частых записей и снимков, ожидающих заблокированную транзакцию. Владение базой фиксируется при открытии редактора.
- Чтение и видео: строки субтитров используют одну общую карту статусов вместо отдельного запроса к словарю на каждую строку.
- Изображения: одновременно выполняется максимум четыре задачи; кэш скачанных изображений ограничен 16 записями.

## PostgreSQL

Миграция `202610260001_sync_indexes.sql` добавляет частичные GIN-индексы JSON-массивов членства и индексы обслуживания. Проверка ссылок при изменении карточек и колод использует соединение по изменённым ключам с исходной таблицей, позволяя параметризованные индексные запросы вместо полного просмотра библиотеки.

RPC до записи проверяет типы присутствующих полей, списки строк, булевы значения, неотрицательные числовые поля и допустимые статусы/оценки. Протокол сохраняет совместимость со старыми неполными записями. RLS, блокировки владельца, атомарность и идемпотентные подтверждения сохраняются.

`prune_sync_staging()` доступна только service_role и удаляет незавершённые части старше 30 дней под блокировкой владельца. Фоновый service-role вызов `delete-account` запускает также эту очистку. После очистки прерванный импорт повторно загружает части. Receipts и tombstones сохраняются для устройств, долго работавших офлайн.

Для рабочего окружения примените миграции 002 и 003 по порядку, затем обновите функцию `delete-account` вместе с `_shared`. Настройка серверного scheduler описана в `RELIABILITY_UPDATE.md`. Локальные проверки не означают публикацию на рабочем сервере.

## Проверяемые свойства

- Импорт 2 000 строк: один bulkAdd, одно обновление членства, корректная статистика.
- Очередь из 105 операций: отправляется целиком без вызова полного toArray очереди или служебной таблицы.
- Повторный replay неизменившихся событий: нет повторной записи прогресса/статистики.
- Новая правка во время подтверждения старой версии не затирается.
- Вход/выход между вкладками и смена аккаунта при заблокированной записи черновика проходят браузерный тест.
- SQL-тесты проверяют индексы, RLS и отклонение повреждённых полей. Интеграционные сценарии проверяют сохранение контрактов RPC после оптимизации.

Эти проверки подтверждают число операций и корректность; они не являются измерением задержки рабочего сервера.
