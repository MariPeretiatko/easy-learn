# Локальные проверки облачной интеграции

Проверки выполняются на отдельном локальном Supabase в Docker. Внешний проект не создан, удалённый CI и Cloudflare Pages не запускались.

## Результат последнего полного локального прогона

68 модульных тестов, 42 существующих production E2E, 7 облачных E2E и 8 SQL-проверок прошли. Дополнительно прошли интеграционные проверки API, удаления аккаунта и очистки изображений.

## Набор проверок

- `npm run check`: строгий TypeScript, достижимость экспортов, модульные тесты, production-сборка и PWA.
- `npm run test:e2e:production`: существующие браузерные сценарии приложения, включая офлайн-запуск и запись.
- `pnpm exec supabase test db`: 8 SQL-проверок схемы, RLS и прав на RPC.
- `npm run test:cloud`: настоящие Auth/PostgreSQL/Storage; изоляция двух аккаунтов, запрет прямых записей, ссылки между владельцами, атомарный RPC, идемпотентность, объединение полей, конфликты, tombstones и атомарный импорт частями.
- `npm run test:cloud:browser`: два независимых браузера, изображение, офлайн-правка, перезагрузка, выход и изоляция; отозванная истёкшая сессия и смена аккаунта во время заблокированной записи; регистрация с настоящим локальным письмом, подтверждение, повторная отправка после реального минутного ограничения, восстановление пароля; перенос полной гостевой библиотеки; неверный пароль и callback; выход в соседней вкладке.
- `npm run test:cloud:delete`: настоящая серверная функция через Deno и локальный Supabase; проверка токена и origin, удаление файлов и аккаунта.

## Измерения тестового сценария

Один из успешных прогонов на полном подготовленном каталоге:

| Сценарий                                                          | Измерение                                                           |
| ----------------------------------------------------------------- | ------------------------------------------------------------------- |
| Создание колоды с изображением, второе устройство и офлайн-правка | 9 RPC-запросов, 9 699 байт исходящих RPC-тел, 8 обращений к Storage |
| Гостевая библиотека                                               | 4 876 локальных карточек: подготовленный каталог и личная карточка  |
| Облачные данные после переноса и предыдущего сценария             | 44 записи, 18 432 байта JSON, из них 2 записи карточек              |

Это измерения конкретного сценария, а не оценка предельного числа пользователей. В RPC-метрику не включены Auth и обычные GET-запросы чтения. JSON-объём не равен физическому месту PostgreSQL с индексами и журналами. Изображение в сценарии маленькое; большие пользовательские файлы расходуют Storage отдельно.

Каталог не отправляется целиком при входе или каждом ответе. Изменения и личное обучение передаются отдельно; на других устройствах тот же каталог загружается из статической сборки.

## Границы проверки

- SMTP, HTTPS, окончательные URL возврата, доставка внешних писем и реальная конфигурация Cloudflare требуют внешнего preview.
- `npm run test:cloud:cleanup` проверяет настоящую серверную очистку: старый orphan удаляется, живые/молодые файлы и файлы незавершённых импортов сохраняются; блокировка записи снимается после завершения.
- Политика очистки старых квитанций/удалений не включена: они сохраняются, чтобы старые клиенты не восстанавливали удалённое.
- Отозванная истёкшая сессия, смена аккаунта при заблокированной записи и выход в соседней вкладке проверены браузером. Доставка внешних писем и окончательные домены требуют внешнего preview.
