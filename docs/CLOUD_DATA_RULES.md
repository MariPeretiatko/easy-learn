# Правила данных первой облачной версии

## Сценарии

| Сценарий             | Поведение                                                                                                                                                                                                                                                                    |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Гость                | Работает в прежней базе `easy-learn`, без аккаунта и сети.                                                                                                                                                                                                                   |
| Регистрация          | Supabase Auth создаёт аккаунт, серверный trigger — профиль. Подтверждение email включает сессию через PKCE callback.                                                                                                                                                         |
| Первый вход          | Открывается отдельная база аккаунта, импортируется статический каталог, загружаются облачные изменения. Гостевая библиотека не присваивается аккаунту автоматически.                                                                                                         |
| Перенос гостя        | Пользователь просматривает объём, может скачать JSON, затем запускает перенос. Исходник сохраняется, совпадения личных материалов получают новые ID с картой соответствия. Начальный прогресс и статистика сохраняются.                                                      |
| Повторный вход       | Открывается локальная база этого аккаунта и продолжается отправка неподтверждённых операций.                                                                                                                                                                                 |
| Второе устройство    | Загружается тот же каталог и личные изменения по серверному курсору; изображения становятся локальными data URL.                                                                                                                                                             |
| Без интернета        | Уже открытая библиотека остаётся доступной; правки записываются в очередь. Новая регистрация и новый вход требуют сети.                                                                                                                                                      |
| Выход/смена аккаунта | Старый интерфейс размонтируется, черновик сохраняется в захваченную им базу, синхронизация останавливается, затем меняется база и настройки. Поздний ответ старого запроса не применяется. Личная база остаётся на диске для повторного входа; это не шифрованное хранилище. |
| Конфликт             | Непересекающиеся поля объединяет сервер. Конкурирующие изменения одного поля сохраняются как конфликт всей операции, доступный в настройках. Можно скачать обе версии.                                                                                                       |
| Удаление             | Отправляется tombstone. Старая офлайн-правка не восстанавливает запись молча; явное восстановление требует выбора локальной версии конфликта.                                                                                                                                |
| Восстановление JSON  | Заменяет библиотеку активного пространства. В аккаунте изменения и удаления отправляются в облако. Старые очереди не стираются: операции сохраняют порядок, а восстановление идёт следующей транзакцией.                                                                     |

| `useSettings`, игровые рекорды                           | Параметры обучения, оформление, предметы, рекорды       | Все текущие настройки привязаны к аккаунту и передаются в preferences. | `libraryImport.ts`, `libraryReorganization.ts`           | Базовый каталог и маркеры                               | Bootstrap выполняется без очереди. ID новых карточек выводятся из нормализованной идентичности, ID колод/коллекций сохраняются из пакета. Личные последующие изменения попадают в очередь. |
| `backup.ts`, `clearData`                                 | Замена и очистка библиотеки                             | Инфраструктурные таблицы очереди/курсора не очищаются пользовательской операцией. Для статистики задаётся начальный снимок.                                                                |
| Supabase Auth                                            | Сессии и пароли                                         | Управляются SDK Auth; не включаются в JSON-копию и таблицы приложения.                                                                                                                     |
| AccountPanel                                             | Имя/аватар, перенос гостя, конфликты                    | Профиль обновляется с RLS; выбор версии и импорт сохраняются локально, затем отправляются.                                                                                                 |

## Совместимость и ограничения

- Старые строковые ID не преобразуются в UUID. Миграция гостевых дубликатов сохраняет карту ID в метаданных аккаунта.
- Редактирование карточки не создаёт отдельный прогресс в каждой колоде. Колоды продолжают ссылаться на общую карточку пользователя.
- Гостевая база сохраняет прежние 11 таблиц и версию 2: новая версия не требует закрытия старой гостевой вкладки. Служебные таблицы и версия 4 применяются только к базам аккаунтов.
- Публичный каталог один для всех; личные правки отправляются только при изменении. Обычный вход не отправляет весь каталог в облако.
- Восстановление копий версии 1 поддерживается. Снимок итогов заменяет прежний набор событий; импортированные исторические ответы не воспроизводятся как новые.
- Журналы удалений и квитанции пока не удаляются. Политика их ограниченного хранения потребует отдельного протокола полной повторной загрузки.
- Универсальный JSONB-протокол читает представление `sync_records`. Содержимое карточек физически отделено от прогресса (`sync_record_data` / `card_progress`); события представлены `review_events` и `activity_events`. Упорядоченные связи остаются массивами, с проверкой ссылок и владельца в атомарном RPC.

Ручные отметки статуса/следующего повторения сохраняются отдельно от вычисляемого SRS и действуют до следующего ответа. Восстановление копии явно заменяет начальный прогресс; обычное редактирование текста не перезаписывает производные счётчики.
