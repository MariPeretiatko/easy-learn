# Обновление надёжности и входа

## Вход и локальная разработка

Обычная сборка требует аккаунт. `/login`, `/register`, восстановление пароля и callback открываются отдельно от учебного интерфейса. Без сессии защищённые адреса перенаправляются на вход с сохранением `next`. Старая база `easy-learn` остаётся на устройстве и переносится через настройки после входа.

Только для автономной разработки можно явно задать `VITE_ENABLE_LOCAL_WORKSPACE=true` при пустом `VITE_SUPABASE_URL`. Не включайте эту переменную в публичной сборке. Браузерные локальные тесты собирают отдельный `dist-e2e`; `dist` сохраняет обязательный вход. `npm run test:auth` проверяет именно публичную сборку.

## Серверное удаление аккаунта

Примените миграцию `202610250002_account_deletion.sql`, затем обновите функцию `delete-account` вместе с `_shared/accountDeletion.ts`. Старый клиент совместим с новой схемой, новый клиент использует RPC `account_deletion_pending`.

Перед первым удалением файлов сервер атомарно сохраняет намерение удаления и блокировку обслуживания. RLS закрывает обычный доступ к данным и изображениям. Ошибка Storage/Auth оставляет задание `pending`; повтор пользователя продолжает удаление оставшихся объектов. Задание не связано каскадным удалением с Auth и сохраняется даже после успешного удаления пользователя, если подтверждение завершения прервалось.

Для автоматического завершения настройте защищённый серверный scheduler: раз в минуту POST на `/functions/v1/delete-account` с `Authorization: Bearer <SERVICE_ROLE_KEY>`. Такой вызов обрабатывает до 10 незавершённых заданий. Ключ хранится только в серверных секретах, не во фронтенде. Мониторинг: `account_deletion_jobs.status`, `requested_at`, `last_error`. Старые завершённые задания можно удалять по принятому сроку хранения; незавершённые нельзя удалять вручную без восстановления операции.

## Очередь и производные данные

Синхронизация пересчитывает только карточки и дни, затронутые принятыми изменениями. Индексы `reviews.wordId` и `activity.date` ограничивают чтение. Полный пересчёт остаётся для восстановления/диагностики и проверяется против инкрементального в тестах.

Ошибки данных сохраняются как `failure:<operation-id>` в `syncMeta`. Операция и зависимые операции остаются в очереди; независимые продолжают отправляться. Сетевые ошибки и ошибки сессии останавливают текущую попытку и автоматически повторяются. В настройках доступны причина, код, скачивание операции и явный повтор. Конфликты сохраняют прежний выбор версий.

## Черновики

Текст и порядок карточек сразу синхронно журналируются в localStorage отдельно для каждого аккаунта. Изменения текста объединяются за 150 мс перед записью в IndexedDB; новые изображения отправляются на запись сразу. Ожидающие снимки объединяются, если предыдущая запись заблокирована. При повторном открытии более свежий журнал восстанавливается с медиа из IndexedDB. Журнал удаляется после успешной записи или публикации. Большие медиа сохраняются асинхронно; до завершения записи действует предупреждение при закрытии. При полном аварийном завершении браузера до записи нового изображения его сохранение гарантировать нельзя.

## Стили и загрузка

`surfaces.css` стал манифестом упорядоченных файлов в `styles/surfaces/`. Файлы отвечают за оболочку, библиотеку, колоду, редактор, упражнения, адаптивность и взаимодействия. Порядок правил сохранён. Это структурный этап рефакторинга; оставшиеся старые переопределения требуют постепенного переноса, а не массового удаления без визуальных проверок.

Экран аккаунта загружает базовые стили; учебная оболочка, IndexedDB и функциональные страницы загружаются отдельно. SDK облака вынесен в стабильный chunk. `npm run check:bundle` контролирует суммарный начальный JavaScript по manifest: максимум 160 КиБ gzip, включая статические зависимости.
